The Notes

03 · what to know before you run

The contributions are scaled copies of the modules' outputs

x   = embed_tokens(ids) * embedding_multiplier
h   = x + self_attn(input_layernorm(x)) * residual_multiplier
out = h + mlp(post_attention_layernorm(h)) * residual_multiplier

attention_output and mlp_output are the modules' outputs times residual_multiplier, the tensors the block adds; decompose, attribute and steer through them. In bfloat16 a write to either contribution moves the other positions by rounding; load in float32 for small edits. On Granite 4.2 the embedding, residual and logit multipliers are 1.

The logits are divided by logits_scaling, and the embeddings multiplied

model.logits is lm_head.output / logits_scaling and project_on_vocab divides too, so a softmax over lm_head.output is sharper than the model's own distribution. layers[0].input is token_embeddings times embedding_multiplier, and embeddings passed as inputs_embeds are multiplied too, so to set what block 0 reads, edit layers[0].input.

The prompt's first token is an attention sink

The tokenizer adds no beginning-of-sequence token, so the prompt's first token takes most of the attention and its stream has a norm many times the other positions'. Leave position 0 out of activation statistics and steering-vector norms.

quirks

Scaled residual adds

A multiplier sits on the residual adds: on a sublayer's output before it joins the stream, on the stream itself, or on the block's whole output.

Embedding multiplier

The model scales the embedding module's output before block 0, so token_embeddings is the unscaled tensor and layers[0].input the scaled one.

Scaled logits

The model multiplies or divides lm_head's output by a scale from the config, so logits is not lm_head's raw output.

Grouped-query attention

Several query heads share each key/value head (num_kv_heads is below num_heads), so an edit to one key/value head reaches every query head in its group. On most families attention_keys and attention_values are served before the repeat, num_kv_heads wide; the notes say where a family expands them first.

04 · nnterp/families/granite.py

Granite (GraniteForCausalLM, IBM Granite 3.x / 4.x dense).

Llama's tree and names, with four scalars from the config applied around it:

  • embedding_multiplier: the model multiplies the embedding module's output by it before the first block, so token_embeddings (the module's output) times the multiplier is layers[0].input.
  • attention_multiplier: the attention's softmax scale in place of 1/sqrt(head_dim), passed to the shared interface; nothing to override.
  • residual_multiplier: the block adds h * residual_multiplier for each sublayer, not h. What reaches the residual stream is the scaled term, so attention_output and mlp_output are the module's output times the multiplier. That product is a computed copy, so each value divides on assignment, and a transform divides an edited copy back into the module's output so in-place edits reach the model.
  • logits_scaling: the model divides the head's output by it, so the family defines project_on_vocab with that step and the logit lens on the last block equals logits.
