03 · what to know before you run

On attention blocks the contributions are the post-norms' outputs

# a DeltaNet block: pre-norm
h   = x + linear_attn(input_layernorm(x))
out = h + mlp(post_attention_layernorm(h))

# an attention block: post-norm, no input_layernorm
h   = x + post_attention_layernorm(self_attn(x))
out = h + post_feedforward_layernorm(mlp(h))

On a DeltaNet block attention_output and mlp_output are the modules' outputs. On an attention block they are the outputs of the norms after the sublayers, so scaling self_attn.output or mlp.output there does nothing to the stream; scale, steer and decompose through attention_output and mlp_output.

q_norm and k_norm span every head

On the attention blocks each takes one RMS over the whole projection before the heads are split, so an edit to one head's slice of q_proj.output reaches the other heads. Edit one head at attention_queries or attention_keys, which no norm follows.

Think-SFT's attention is rotary

The released configs set rope_theta to null, and the attention blocks then apply no rotary embedding. Olmo-Hybrid-Think-SFT-7B sets rope_parameters itself to null, which transformers fills with a theta of 10000, so its attention blocks do rotate their queries and keys.

quirks

Hybrid

Some blocks mix tokens with a recurrent mixer (layers[i].linear_attn), others with attention (layers[i].self_attn).

Post-norms only

Every block, or some, norms each sublayer's output and not its input: the sublayer reads the raw stream, and the stream receives the post-norm's output.

Query/key norms

On every block or some, the attention norms its projected queries and keys (q_norm and k_norm on most families); attention_queries and attention_keys are read after the norms.

Blocks without rotary

Some blocks, or all, apply no rotary embedding (NoPE). In those blocks attention_queries and attention_keys carry no position, and only the causal mask tells positions apart.

04 · nnterp/families/olmo_hybrid.py

OLMo-Hybrid (OlmoHybridForCausalLM).

Llama's containers over two block classes, chosen by config.layer_types:

  • OlmoHybridLinearAttentionDecoderLayer (linear_attention) is pre-norm, as Llama: input_layernorm -> linear_attn (a gated DeltaNet, see nnterp.LinearAttention), then post_attention_layernorm -> mlp, each added to the stream as the module returns it.
  • OlmoHybridAttentionDecoderLayer (full_attention) is OLMo-3's post-norm sandwich: self_attn -> post_attention_layernorm and mlp -> post_feedforward_layernorm, the post-norms' outputs added to the stream; it has no input_layernorm, so the block input enters the attention.

Each block has self_attn or linear_attn, never both. The attention runs the shared eager forward (query and key norms before it; no rotary embedding when the checkpoint sets no rope_theta), so its contribution is OLMo-3's override at the post-attention norm. Both block classes hold one MLP class, OlmoHybridMLP, whose contribution is its own output on a linear block and the post-feedforward norm's output on an attention block, so mlp_output is a EProperty whose key is chosen by the parent block's layer type. The DeltaNet calls transformers' torch_chunk_gated_delta_rule / torch_recurrent_gated_delta_rule as Qwen3-Next does, so the base LinearAttention holds; with linear_allow_neg_eigval the betas are doubled before the kernel and lie in (0, 2).
