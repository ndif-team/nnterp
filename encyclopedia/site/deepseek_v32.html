DeepSeek-V3.2

Latent attention over only the 2048 keys a lightning indexer scores best for each query, and a mixture with a shared expert that chooses experts by sigmoid score plus a selection bias and weights them without the bias.

The Notes

03 · what to know before you run

The block, in order

h   = x + self_attn(input_layernorm(x))      # sparse latent attention
out = h + mlp(post_attention_layernorm(h))   # dense on blocks 0-2, a mixture after

Llama's pre-norm block and Llama's names. The block adds each sublayer's output to the stream and returns a tensor, so the identity is the plain sum on a dense block and on a mixture block:

with model.trace(prompt):
    x = model.layers[1].input.save()
    attn = model.layers[1].self_attn.attention_output.save()
    mlp = model.layers[1].mlp.mlp_output.save()
    out = model.layers[1].layer_output.save()

torch.testing.assert_close(x + attn + mlp, out)

config.mlp_layer_types says which blocks are dense: blocks 0 to 2 on every checkpoint (first_k_dense_replace 3), a mixture on the other 58. The configs carry one multi-token-prediction block (num_nextn_predict_layers 1), stored after the last block; transformers does not build it, so model.layers has 61 blocks.

Latent attention: every head's key comes from one latent

attention_queries and attention_keys are qk_head_dim wide (qk_nope_head_dim + qk_rope_head_dim, 128 + 64 = 192), attention_values and attention_head_outputs head_dim (v_head_dim, 128). transformers sets the config's head_dim to qk_rope_head_dim, the rotary width (64); no served value is that wide. Queries go through a compressed rank (q_lora_rank 1536): q_a_proj, q_a_layernorm, then q_b_proj, with no q_proj module. Keys and values are expanded for every head from one latent per token (kv_lora_rank 512), so attention_keys has num_heads (128) heads. The last 64 dimensions of every head's key are one rotary key that all heads share.

attn = model.layers[1].self_attn
with model.trace(prompt):
    q = attn.attention_queries.save()          # [1, 128, seq, 192]
    k = attn.attention_keys.save()             # [1, 128, seq, 192]
    v = attn.attention_values.save()           # [1, 128, seq, 128]

assert torch.equal(k[:, 0, :, -64:], k[:, 1, :, -64:])   # one rotary key

The rotary part is served de-interleaved

The attention rotates pair (2i, 2i + 1) of the projection into dimensions i and i + 32 of the rotary part. The forward always does this; the config has no rope_interleave key to switch it. attention_queries[..., -64:] and attention_keys[..., -64:] are in that rotate-half order: at position 0, where rotary is the identity, the served rotary part is q_b_proj's even dimensions followed by its odd ones.

with model.trace(prompt):
    proj = attn.q_b_proj.output.save()
with model.trace(prompt):
    q = attn.attention_queries.save()

rope = proj.view(1, -1, model.num_heads, model.qk_head_dim)[0, 0, 0, -64:]
torch.testing.assert_close(q[0, 0, 0, -64:], torch.cat([rope[0::2], rope[1::2]]))

The query scale carries YaRN's factor

Every checkpoint extends the context with YaRN (rope_scaling factor 40, mscale_all_dim 1.0), and the attention multiplies the scores by qk_head_dim ** -0.5 times 1.87 (self_attn.scaling, 0.1352), not by qk_head_dim ** -0.5 (0.0722) alone; recompute attention_scores from the queries and keys with self_attn.scaling.

Up to 2048 tokens the sparse attention is plain causal attention

A lightning indexer (self_attn.indexer: index_n_heads 64 heads of index_head_dim 128) scores every key for every query and keeps the index_topk (2048) best. The attention sets the other keys' mask entries to the dtype's minimum before it calls the attention function. It does this under eager and under the default sdpa load alike, so both loads run the same sparse computation; the interior values need attn_implementation="eager". attention_scores carry that mask, so a dropped key reads like a future one. attention_probabilities is the dense [batch, num_heads, query, key] pattern, exactly zero outside each query's selection.

The selection is self_attn.indexer.output, int32 key indices of shape [batch, query, min(index_topk, seq)]; it has no standard name. The indexer ranks future keys last but does not drop them. On a prompt of up to 2048 tokens each row therefore lists every position, the causal mask removes the future keys, and the pattern is plain causal: row t has t + 1 nonzero entries.

with model.trace(prompt):
    sel = attn.indexer.output.save()           # [1, seq, min(2048, seq)]
    probs = attn.attention_probabilities.save()

rows = (probs[0, 0] != 0).sum(-1)
assert torch.equal(rows, torch.arange(1, rows.numel() + 1))   # plain causal

A written pattern is used as written, so a write can give weight to a key the indexer dropped. The indexer runs under torch.no_grad(): no gradient reaches its projections, and the selection does not move with a gradient-based attribution.

The mixture: sigmoid scores, a selection bias, renormalized weights

256 routed experts, 8 per token, and one shared expert every token runs through. router_logits are the float32 logits before the sigmoid, and before the selection bias (router.e_score_correction_bias). The bias is added to the sigmoids only to choose: the experts sit in n_group 8 groups, each group scored by the sum of its two best biased scores, and a token takes its 8 experts from its best topk_group 4 groups. expert_weights are the chosen experts' sigmoids without the bias, renormalized to sum to one (norm_topk_prob) and multiplied by routed_scaling_factor, so they sum to 2.5 at every token. A written router_logits moves both the choice and the weights; a written bias moves only the choice.

moe = model.layers[3].mlp
with model.trace(prompt):
    logits = moe.router_logits.save()
    w = moe.expert_weights.save()
    idx = moe.expert_indices.save()
    routed = moe.routed_output.save()
    shared = moe.shared_expert_output.save()
    out = moe.mlp_output.save()

chosen = logits.sigmoid().gather(-1, idx)
scale = model.config.routed_scaling_factor
torch.testing.assert_close(w, chosen / chosen.sum(-1, keepdim=True) * scale)
torch.testing.assert_close(routed + shared, out)

The shared expert runs after the routed ones, so shared_expert_output is read after routed_output. Ablating an expert is zeroing the weight of every slot that chose it; the other slots keep their weights, so the token's weights then sum to less than 2.5:

with model.trace(prompt):
    moe.expert_weights = moe.expert_weights.masked_fill(moe.expert_indices == 3, 0)
    ablated = model.logits.save()

Blocks 0 to 2 have a dense MLP: support() reports every mixture value missing there.

quirks

Latent attention

Keys and values are projected up from a small latent shared by the heads; queries and keys are qk_head_dim wide, values head_dim wide.

Sparse attention

On every block or some, an indexer picks the top keys for each query; the pattern is served as a full query × key tensor, zero outside the picked keys.

Interleaved rotary

Rotary rotates adjacent pairs of dimensions (2i, 2i + 1), not i with i + rot/2 as rotate_half does, so a query or key head's dimensions pair up differently from a rotate_half family's. Where the attention rotates the even and odd slices (apply_rotary_pos_emb_interleave), the rotated queries and keys come out in rotate_half order, evens first.

Mixture of experts

On every block or some, the MLP is a mixture of experts: layers[i].mlp serves router_logits, expert_weights, expert_indices and expert_outputs, though some families leave one or more of them unavailable.

Dense first blocks

The first blocks have a dense MLP and the rest a mixture of experts, so the mixture's values exist only from the first mixture block on.

Under eager and sdpa the selection is folded into the attention mask (every unselected key set to the dtype's minimum) before the shared attention_interface call, so the interior is the base's, read on the interface:

  • attention_scores are the scaled scores with that sparse mask added, so an unselected key reads as the dtype's minimum, like a future one.
  • attention_probabilities is the dense [batch, num_heads, query, key] pattern of the sparse attention: exactly zero outside each query's selected keys, rows summing to one over the selection. A written pattern is used as written, so a write can put weight on keys the indexer did not select.

While a prompt is no longer than index_topk (2048 on the released checkpoints) the indexer selects every causal key and the pattern is the dense causal one. The indexer's selection is self_attn.indexer.output, the [batch, query, min(index_topk, keys)] int32 key indices; it has no standard name. On a prompt shorter than index_topk it holds every key, future ones included (masked in the index scores, so ranked last), and the causal mask removes those. The first first_k_dense_replace blocks (per mlp_layer_types) have a dense MLP, the rest a mixture of experts. The sizes are DeepSeek-V2's.
