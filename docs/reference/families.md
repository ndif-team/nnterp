# Families

## What this is for

A family is one module under `nnterp/families/`, named after `config.model_type`. This page is the lookup table for the 98 shipped families (108 pinned checkpoints: Falcon's 7B and 40B layouts share one module, Gemma-3 and Gemma-4 each pin a multimodal wrapper beside a text checkpoint, Gemma-4 a third for the 26B-A4B layout, and the vision side pins six more wrappers, Gemma 3's and Llava's for the towers and four for the text names on a wrapper, and the four Qwen-VL families pin their wrappers, which are their only checkpoints; the Qwen3.5 tiny checkpoints are pinned once and loaded both ways): where each one's native modules are, which standard values the family relocates and how, and what `support()` says a checkpoint of that family does not have. The second half groups the families by quirk, so a recipe that must survive one quirk (a tuple block, a sandwich norm, a sink) can see at once which families it must survive on.

Every row but OLMo-3's, Ministral's, Kimi K2's and Kimi-Linear's was checked by loading the pinned tiny checkpoint with `dispatch=True, attn_implementation="eager"` and diffing its `support()` against the table (OLMo-3's tiny checkpoint loads only through the config rewrite its test performs, Ministral's only with the tokenizer its test supplies, and Kimi K2's and Kimi-Linear's only through the config rewrites their tests perform, so their rows rest on the suite). Under an eager load every swept checkpoint reports every value available except OPT and XGLM (no MLP module, so no `mlp.*` key), the hybrids (each block has `self_attn` or `linear_attn`, and the per-token state needs `route_kernels(model.family, "torch")`) and Gemma-4's 26B-A4B-layout checkpoint (no per-layer embeddings, so no `per_layer_output`). Gemma-4's text checkpoint loads only through the rewrite its test performs, so its row rests on the suite. The reason strings below are what `support()` returns on transformers 5.17, quoted from a live `support()` of the pinned checkpoints; a reason that names an optimized kernel names the operation and the package of the process that reports it.

## Canonical pattern

```python
from nnterp import StandardizedTransformer

model = StandardizedTransformer("meta-llama/Llama-3.1-8B", dispatch=True, attn_implementation="eager")

print(model.family.__name__)                                         # nnterp.families.llama
print(model.family.RENAME)                                           # the aliases: {'model.embed_tokens': 'embed_tokens', 'model.layers': 'layers', 'model.norm': 'norm'}
print(model.layers[0].self_attn is model.model.layers[0].self_attn)  # True: an alias, not a copy
print({name: reason for name, reason in model.support().items() if reason})   # {} : Llama has every value under eager
```

The same four lines on a checkpoint of any other family print that family's module, its `RENAME`, `True`, and the dict the tables below predict.

## Names, shapes and quirks

The same rows again. "Native" is what `RENAME` maps onto the standard name, in the order embeddings / blocks / final norm, then attention / MLP inside a block, then the block's norms; `lm_head` is `lm_head` everywhere (GPT-NeoX-Japanese's head is `embed_out`, and so was GPT-NeoX's on old releases; both bind). A block norm listed here is aliased `input_layernorm` / `post_attention_layernorm` only where the row says so; what a norm produces is `self_attn.input` / `mlp.input` on every family regardless.

"Tuple" is `Layer.returns_tuple`: whether the block returns `(hidden_states, ...)`. The attention module returns `(attn_output, attn_weights)` on every non-hybrid family (GPT-NeoX-Japanese's adds its `dense_bias` third); a hybrid's `linear_attn` returns a bare tensor. `attention_output`, `mlp_output` and `layer_output` unwrap these on every family.

"Overrides" names the values the family points somewhere other than the base class does. Everything not named is the base: `layer_output` at the block's output, the contributions at the module outputs, the interior on `attention_interface_1`.

## Quirks by theme

### Tuple blocks

`gptj`, `gpt_neo`, `codegen`, `gpt_neox_japanese`, `bloom`, `mpt`, `falcon`, `glm_moe_dsa`, `bamba`, `falcon_h1`, `zaya` set `Layer.returns_tuple = True`: the block returns `(hidden_states, ...)`. `layer_output` is the first element on every family; assigning it keeps the other elements; `skip_layers` hands back `(hidden, None)` on these and a bare tensor elsewhere (on GLM-5 the `None` is the selection a `shared` block needs). Separately, every softmax attention module returns `(attn_output, attn_weights)` (GLM-5's adds the selection third, JetMoE's its router logits, GPT-NeoX-Japanese's its `dense_bias`) and GPT-OSS's MLP returns `(hidden_states, router_scores)`; `attention_output` and `mlp_output` take the first element, so a recipe never sees the tuples.

### Sandwich norms

`gemma2`, `gemma3_text`, `gemma4_text`, `gemma4_unified_text`, `olmo2`, `olmo3`, `exaone4`, `flex_olmo`, and the attention blocks of `olmo_hybrid`: the residual stream receives a post-sublayer norm's output, not the module's, so `attention_output` is an `EProperty` keyed `../post_attention_layernorm.output` and `mlp_output` one keyed `../post_feedforward_layernorm.output`. `afmoe` keys `../post_attention_layernorm.output` and `../post_mlp_layernorm.output` (its pre-MLP norm is `pre_mlp_layernorm`); `glm4` keys `../post_self_attn_layernorm.output` and `../post_mlp_layernorm.output`, and there `post_attention_layernorm` is the pre-MLP norm, the Llama meaning; `hyperclovax` keys `../post_norm1.output` and `../post_norm2.output` and scales them (below). On these families `post_attention_layernorm` *follows* the attention. Gemma-2/3/4 also norm before each sublayer (`input_layernorm`, `pre_feedforward_layernorm`); OLMo-2/3, EXAONE-4 and FlexOlmo have only the post-norms, so `self_attn.input` is the block input and no `input_layernorm` exists. `vaultgemma` is Gemma's layout with the pre-norms only: the base holds. OLMo-Hybrid's linear blocks are pre-norm and share the attention blocks' MLP class, so its `mlp_output` names its key per block ([Hybrids](#hybrids)).

### Residual added inside the module

`bloom` (both sublayers, via `dropout_add`) and `mpt` (the MLP only) take the residual as an argument and return a residual-stream state. The contributions are `EProperty` values keyed inside the forward, at the tensor before the add: BLOOM's `source.dropout_add_0.input` for both, MPT's `source.F_dropout_0.output` for the MLP. On `dbrx` the residual is added by `norm_attn_norm`, outside the attention module, so the module's own output is its contribution and the base holds.

### Scaled residual adds

`falcon_h1` scales each mixer's output (`ssm_out_multiplier`, `attention_out_multiplier`) before the add; its `attention_output` values are the block's own bindings of the products, so they are the tensors the block adds and need no arithmetic. `granite`: the block adds `h * residual_multiplier` for each sublayer (0.22 on granite-4.1-3b; 1.0 on the pinned tiny checkpoint, so the test also runs a copy with 0.22). `attention_output` and `mlp_output` are the scaled terms, the module's output times the multiplier, so the contribution identity holds. The value is a computed copy: assigning divides by the multiplier before it is swapped in, in-place edits reach the model through an `eproperty` transform that divides the edited copy back, and a read with no edit leaves the forward bit-identical. `self_attn.output` and `mlp.output` stay the unscaled module outputs. `granitemoe`, `granitemoeshared`, `granitemoehybrid`, `granite_swa` and `granitemoe_swa` are the same pattern; a mixture (and GraniteMoE-Hybrid's Mamba-2 mixer and shared expert) keeps no config, so those envoys read the multiplier off their parent block, with whatever else a key needs (`shared` on GraniteMoE-Shared's `Mlp`, `has_experts` on GraniteMoE-Hybrid's); each of ZAYA's sublayers reads the merge that follows it through its parent. Where no module returns what the block adds, the value is the block's binding of it, scaled the same way: GraniteMoE-Shared's and GraniteMoE-Hybrid's `mlp_output` is the routed experts plus the shared expert (`hidden_states_4`), and a write to it replaces both. `hyperclovax` scales the post-norms' outputs (a sandwich block) the same way and multiplies its logits by `logits_scaling`.

On all of these, and on `zaya` below, a write reaches the model by dividing the *whole* edited copy back into the module's output, so the positions you did not edit are rewritten too and come back changed by rounding: about 1e-7 relative in float32, one or two units in the last place in bf16. In bf16 that is not negligible next to a small edit: on granite-3.0-1b-a400m an edit at one position moved the logits at earlier positions, which it cannot reach causally, by 0.17, against 0.19 at the edited position. Load these families in float32 for fine-grained edits (one position, one head's worth, a small steering vector). A read with no edit hands the module's output back untouched.

`zaya` merges each sublayer's output `o` into the stream `r` with a `ZayaResidualScaling`: `(o + hidden_states_bias) * hidden_states_scale + (r + residual_bias) * residual_scale`. `attention_output` and `mlp_output` are the first term, a computed copy inverted on assignment as on Granite; the second rescales the stream itself, so the identity is `h == (input + residual_bias) * residual_scale + attention_output`, `layer_output == (h + residual_bias) * residual_scale + mlp_output` with each merge's own parameters (`layers[i].post_attention_residual_scale._module`, `post_mlp_residual_scale._module`), the plain one only at their initial values. `doge` gates the stream only, not the contributions: `h == input_residual * input + attention_output`, `layer_output == post_attention_residual * h + mlp_output`, with per-channel gates that start at one; the contributions are the modules' outputs and nothing is computed or divided for you.

`gemma4_text` and `gemma4_unified_text` scale the block's sum, not each sublayer: `hidden_states *= layer_scalar` ends the block, in place, with a per-block buffer that is far from one on the released weights (0.005 to 0.99 on the released E2B, E4B, 12B, 26B-A4B and 31B weights; gemma-4-12B's block 11 is 0.005, and every size's first block lies between 0.018 and 0.11). The contributions are the post-norms' outputs, unscaled, so `layer_output == (input + attention_output + mlp_output [+ per_layer_output]) * layer_scalar`, and what a block adds reaches a later stream multiplied by this block's scalar and every later one. The scalar is `layers[i]._module.layer_scalar`; nothing is computed or divided for you.

### Hyper-connection residual

`deepseek_v4` carries `hc_mult` parallel copies of the residual stream between blocks
(4 on the released and the tiny checkpoints), and its `layer_output` and `layers[i].input`
are that tensor, `[batch, seq, streams, hidden]`, the block's own, so writes land natively.
It is the one exception to one layout per value: `layer_output` is `Streams` here and
`Residual` everywhere else. Each sublayer reads a weighted collapse of the streams and
returns `[batch, seq, hidden]`; `attention_output` and `mlp_output` are those outputs,
unscaled, as on Gemma-4. The hyper-connection before each sublayer (`attn_hc`, `ffn_hc`)
returns `(post, comb, collapsed)`, served as `attention_post` / `mlp_post`
(`StreamWeights`, `[batch, seq, streams]`, each in (0, 2)) and `attention_comb` / `mlp_comb`
(`StreamMixing`, `[batch, seq, streams, streams]`, doubly stochastic by a Sinkhorn
projection, applied transposed); all four are float32 and writable. The identity is
documented, not additive:

```
layer_output == mlp_combᵀ · (attention_combᵀ · input + attention_post ⊗ attention_output) + mlp_post ⊗ mlp_output
```

exact on every block of the tiny checkpoint in float32. Its stream mean is additive,
`layer_output.mean(2) == input.mean(2) + attention_post.mean(-1, keepdim=True) *
attention_output + mlp_post.mean(-1, keepdim=True) * mlp_output`, within about 2e-6 relative
(the Sinkhorn projection's rows sum to one only approximately). The model reads the streams
out with `hc_head`, a learned content-dependent weighting, before `norm`; the family's
`project_on_vocab` does the same, so the lens at the last block equals `logits` exactly.
`skip_layers` and `steer` work unchanged (a `[hidden]` steering vector adds to every
stream). Cross-family code that assumes `layer_output` is rank 3 runs here and answers per
stream; `lm_head(norm(layer_output))` returns `[batch, seq, streams, vocab]` without an error.

### Own attention arithmetic

`gptj`, `gpt_neo`, `codegen`, `gpt_neox_japanese`, `xglm`, `bloom`, `mpt`, `falcon` do not call `attention_interface_1`; each maps the same six interior names onto its own operations (the table above lists them). GPT-J, GPT-Neo, CodeGen and GPT-NeoX-Japanese read them around a `self._attn(query, key, value, mask)` call: its arguments are the queries, keys and values, its first return the head outputs. Six present `attention_head_outputs` as a transposed view (`seq_first`) because their arithmetic keeps heads first; BLOOM and XGLM view them from `[batch * heads, seq, head_dim]`, and XGLM serves every other interior value the same way, a view of the flattened tensor its `bmm` takes. GPT-J's, GPT-Neo's and Falcon's values carry `needs_eager`, which a default load never trips on GPT-J and GPT-Neo (eager is their only non-flash path in transformers) and does trip on Falcon under its default `sdpa`; BLOOM's, MPT's, CodeGen's, XGLM's and GPT-NeoX-Japanese's carry no `attn_implementation` predicate, since their attention has no other implementation. Where the scale sits differs: GPT-Neo has none, CodeGen divides after adding the mask, XGLM scales the queries as it projects them, GPT-NeoX-Japanese folds it into a `baddbmm`. Falcon's pattern is the softmax output itself (no dropout follows). GPT-Neo's attention sits one module down, inside the `attn` wrapper, and `self_attn` names that inner module. A family that has not mapped an interior value would mark it `unavailable(NOT_ON_INTERFACE)`; none of the shipped ones does.

### Attention sink

`gpt_oss`: each head carries a learned logit that joins the softmax as one extra key column and is dropped afterwards. `attention_probabilities` (the dropout output) is already without that column, so its rows sum to less than one (`Attention.SINK = True`); `attention_scores` is read one step earlier, at the `attn_weights_1` binding inside the interface, the masked scores just before the sink column is concatenated. `softmax(attention_scores)` therefore does not reproduce the pattern without appending the sink column and subtracting the row max in the scores' dtype.

`deepseek_v4` has the same sink on every block (`s_aux=self.sinks`, softmax with the row max subtracted), and reads `attention_scores` at the same binding with `SINK = True`; on a compressed block the scores and the pattern carry the compressor's key columns after the token keys.

`mimo_v2_flash` carries the same sink on its sliding-window blocks only (`sinks` is `None` on a full block), with the same softmax: the family reads `attention_scores` at `attn_weights_1` on both block types and sets `SINK = True`, which holds for the sliding blocks; a full block's rows sum to one.

`granite_swa` and `granitemoe_swa` carry a learned per-head sink too, but not in the softmax: the eager forward takes the softmax over the real keys, mixes the values with it, and then scales each query's head output by `sigmoid(logsumexp(scores) - sink)`, the share a softmax with the sink as one more logit would leave on the real keys. So `attention_probabilities` rows sum to one, `softmax(attention_scores)` reproduces them, `attention_head_outputs` carry the scale (between 0.009 and 0.95 on one block of granite-swash-2b), and `SINK` is `False`. Writing the pattern there does not set what a head writes, since the scale comes after it; edit `attention_head_outputs`. The softmax scale is `attention_multiplier` (`attn._module.scaling`, 0.0078 on granite-swash-2b), not `1/sqrt(head_dim)`. The eager forward spells its softmax and dropout `F.softmax` / `F.dropout`, so both values are redefined on those operations.

### Latent attention

`deepseek_v2`, `deepseek_v3`, `kimi_k2`, `deepseek_v32`, `glm_moe_dsa`, `glm4_moe_lite`, `youtu`, and the attention blocks of `kimi_linear`: queries and keys are `qk_head_dim = qk_nope_head_dim + qk_rope_head_dim` wide, values `v_head_dim` (what the family's `head_dim` returns), and the interface receives `num_heads` key/value heads whatever `num_key_value_heads` says (`KV_HEADS_EXPANDED` in the suite). The root publishes `qk_head_dim` for this; `attention_queries` is laid out `batch heads seq qk_head_dim` on every family for the same reason.

### Sparse attention

`deepseek_v32`, `glm_moe_dsa`: DeepSeek Sparse Attention. A lightning indexer (`self_attn.indexer`, its own small projections) scores every key for every query and keeps the `index_topk` best; under eager the others are masked to the dtype's minimum before the shared interface, so the interior values are the base's and the pattern is the sparse one, kept dense: `attention_probabilities` is `[batch, heads, query, key]`, exactly zero outside each query's selection, rows summing to one over it. `attention_scores` carry the mask, so an unselected key reads like a future one. A written pattern is used as written, so a write can give weight to a key the indexer dropped. `index_topk` is 2048 on the released checkpoints: a shorter prompt selects every causal key and the pattern is dense causal (the suite also runs each tiny checkpoint with `index_topk: 2`, where its three-token prompt drops a key). The selection itself has no standard name: `self_attn.indexer.output` on DeepSeek-V3.2 and on GLM-5's `full` blocks, `self_attn.output[2]` on every GLM-5 block.

### Mixtures of experts

39 families run a mixture of experts, and on every one the mixture is a `Moe` (`nnterp/components/moe.py`) with the six values of [../usage/mixture-of-experts.md](../usage/mixture-of-experts.md): `router_logits`, `expert_weights`, `expert_indices`, `expert_outputs`, `routed_output`, `shared_expert_output`. The family keys a `Moe` subclass on its MoE module class (its `Mlp` where every MLP is a mixture; a `Moe` beside its `Mlp` where dense blocks come first or alternate) and aliases its router `router` (from `gate`) and its shared expert `shared_experts` (from `shared_expert`, `shared_mlp`). Where the blocks are: `deepseek_v3`, `kimi_k2`, `glm4_moe` and `dots1` after `first_k_dense_replace` dense blocks; `glm4_moe_lite`, `deepseek_v32`, `glm_moe_dsa`, `kimi_linear`, `mimo_v2_flash` and `laguna` per `mlp_layer_types`; `deepseek_v4` on every block (the `hash_moe` blocks route by token id); `llama4_text` on `moe_layers`; `gemma4_text` under `enable_moe_block`; `ernie4_5_moe` per `moe_layer_start_index`, `moe_layer_end_index`, `moe_layer_interval`; `afmoe` after `num_dense_layers`; `granitemoehybrid` when `num_local_experts > 0`; `doge` under `is_moe`; the rest on every block.

### Borrowed keys and values

`gemma4_text` and `gemma4_unified_text`: the last `num_kv_shared_layers` blocks (20 of 35 on E2B, 18 of 42 on E4B) have no `k_proj` / `v_proj`. Each takes the keys and values of the last block of its kind (sliding or full) before the sharing starts, out of a dict the forward passes down the stack, and attends with them. `attention_keys` and `attention_values` are served as a copy private to the block, on every Gemma-4 block: an edit, in place or by assignment, is handed back as that block's own attention argument, so it changes what that block attends with and nothing else, and the dict keeps the source block's tensors as computed. To change the shared keys or values for every borrower, edit each block that attends with them, or edit the source block's `k_proj` / `v_proj` output, which they are computed from. On `attention_k_eq_v` checkpoints (26B-A4B, 31B) the full blocks have no `v_proj`: their values are `v_norm(k_proj(x))`, the keys' projection before `k_norm` and the rotary embedding. Skipping a source block leaves its borrowers nothing (`KeyError` in transformers); skip borrowers, or the whole shared tail.

### Gated query

`qwen3_next`, `qwen3_5_text`, `qwen3_5_moe_text`: `q_proj` produces the query and a gate side by side, so its `out_features` is `2 * num_heads * head_dim` (`QUERY_GATED`). `attention_queries` on the attention block is still `[batch, heads, seq, head_dim]`: the gate is split off before the interface.

### Parallel blocks

One norm's output feeds both sublayers and the block sums `x + attn + mlp`: `gpt_neox` (`use_parallel_residual`; two norms, both of the block input), `phi` (one `input_layernorm`), `gptj` and `codegen` (`ln_1`), `stablelm` (`use_parallel_residual`; `input_layernorm`), `cohere` and `cohere2` (`input_layernorm`), `falcon` 7B (`input_layernorm`) and 40B (`ln_attn`, `ln_mlp`, both of the block input, before either sublayer runs). `mlp.input` is that norm's output, not a mid-block stream, and the contribution identity `input + attention_output + mlp_output == layer_output` holds as on a sequential block. `gpt_neox_japanese` has GPT-NeoX's names but a sequential block.

### Hybrids

`qwen3_next`, `qwen3_5_text`, `qwen3_5_moe_text`, `olmo_hybrid`, `kimi_linear`: `config.layer_types` is `linear_attention` on three blocks in four and `full_attention` on the fourth (one in two on OLMo-Hybrid's tiny checkpoint; Kimi-Linear's released checkpoints end on a second full block). A block has `linear_attn` (a `LinearAttention`) or `self_attn` (an `Attention`), never both, so `support()` reads as per-block dicts: `"no self_attn module on this block"` on the DeltaNet blocks, `"no linear_attn module on this block"` on the attention block. The DeltaNet values are read at the delta-rule kernel call, chunked on a prompt and recurrent on a decode step, and need transformers' pure-torch kernels (`needs_torch_kernels`). The per-token `state` and `states` need `route_kernels(model.family, "torch")` before tracing the layer (`needs_recurrent_routing`); `support()` reports that instruction until then. Decide which blocks have `self_attn` outside the trace. OLMo-Hybrid's two block types are two classes that norm in opposite places (pre-norm linear blocks, post-norm attention blocks) around one MLP class, so its `mlp_output` is an `EProperty` with a key function (`"../post_feedforward_layernorm.output"` on an attention block, `"output"` on a linear one); the identity holds on every block of both types. Kimi-Linear's mixer is Kimi Delta Attention, a gated DeltaNet whose `decays` are one per key channel (`[batch, seq, heads, key_dim]`, `ChannelGates`) read at transformers' own KDA kernels; transformers names it `self_attn`, so the family aliases it `linear_attn` by class and clears `self_attn` on its blocks.

### State-space mixers (Mamba-1)

`mamba`, `falcon_mamba`, and the Mamba blocks of `jamba`: the mixer is Mamba-1's selective scan, `linear_attn` (a `SelectiveScan`), read at `mamba_selective_scan` on a prompt and `mamba_selective_state_update` on a decode step. The kernel's tensors are channel-first; every value is a tokens-first view. `C` / `B` / `x` are `attention_queries` / `attention_keys` / `attention_values`, the step size `softplus(dt + dt_bias)` is `betas`, `dt * A` is `decays` (per channel and state dimension). With `mamba_ssm` installed transformers dispatches both kernels to its CUDA kernels, which have no source and do not run on CPU: `route_kernels(model.family, "torch")` before the first trace, after which the scan is itself the token loop and `state` / `states` are available without a second kernel. Mamba and Falcon-Mamba blocks have no attention and no MLP, so `support()` lists neither and the identity is `input + attention_output == layer_output`. See [../usage/selective-scan.md](../usage/selective-scan.md).

### State-space mixers (Mamba-2)

`mamba2`, `nemotron_h`, `bamba`, `falcon_h1`, `granitemoehybrid`: the Mamba-2 (SSD) mixer is `linear_attn`, a `StateSpace` ([../usage/state-space.md](../usage/state-space.md)). `C`, `B` and `x` are `attention_queries`, `attention_keys` and `attention_values`, `dt` is `betas`, `A * dt` is `decays`, and the state is served `[batch, heads, state_dim, head_dim]`. The values are read at `mamba2_chunk_scan` on a prompt and at `mamba2_selective_state_update` on a decode step and need transformers' pure-torch kernels: with `mamba_ssm` installed they report `needs_torch_kernels` until `route_kernels(model.family, "torch")`, and on a CPU the optimized kernels do not run at all. The state after every token is `states` / `state_after(t)` once `chunk_per_token(model)` sets each mixer's chunk size to 1; `state` and `set_state_after` are unavailable on every Mamba-2 mixer (`STATE_OP` is `None`, and the chunk scan computes every boundary state in one step). `betas` and `decays` are assignable, written back into the kernel's `dt`, and both are views of that one argument: assigning `decays` rewrites `betas` too (`decays = 0`, "keep everything", sets `dt` to zero and so zeroes every write), `betas[:, t] = 0` is the exact "skip this token's write" (the state after `t` equals the state after `t - 1` bit for bit), and assigning `betas` back unchanged is not a no-op: the round trip through the softplus's inverse moves float32 logits by about 1e-4 and bf16 logits by up to 1.0 on mamba2-130m. An in-place edit of either does not reach `dt`; assign. On a decode step read `state_output` before `attention_head_outputs` ([../usage/state-space.md](../usage/state-space.md#gotchas)). Mamba-2 has neither attention nor an MLP; Nemotron-H holds one sublayer per block under one native name, `mixer`, so its `Layer` names it by class (a class-keyed `RENAME` entry); Bamba is Qwen3-Next's shape with a Mamba-2 mixer; Falcon-H1 runs both mixers in parallel in every block. GraniteMoE-Hybrid is Bamba's shape with Granite's multipliers: each mixer's `attention_output` is its output times `residual_multiplier`, and `mlp` is the shared expert standing for the block's feed-forward, whose `mlp_output` is the block's binding of both experts' sum. `zamba2` shares the mixer but is not shipped: its shared transformer's output is projected and added to the Mamba-2 mixer's input rather than to the residual stream, so `attention_output` and `mlp_output` have no residual-stream meaning there.

### No MLP module

`mamba2` has no MLP (and no attention): the block is the mixer alone. `opt` and `xglm`: `fc1`, the activation and `fc2` sit on the block, so `layers[i].mlp` does not exist and `support()` lists no `mlp.*` key (a module no block has is not listed; read `support().get("mlp.mlp_output")`). `layers[i].fc2.output` is what the block adds (the suite checks the contribution identity with it). The block's own `final_layer_norm` is the pre-MLP norm and keeps its native name, since a single-component alias would also bind on the decoder's final norm.

### dtype

`falcon_h1`'s `yujiepan/falcon-h1-tiny-random` is bf16 with the released µP multipliers (`attention_out_multiplier` 0.0375, `mlp_multipliers` down 0.011): in bf16 some writes round away, so the suite loads it with `dtype=torch.float32`. `dbrx`'s pinned tiny checkpoint is fp16 with weights of std 0.02: its attention scores round to a uniform pattern, which makes the queries inert and every layer's pattern identical, so the suite and the sweep load it with `dtype=torch.float32`. Real DBRX checkpoints need nothing special. `deepseek_v4`'s `yujiepan/deepseek-v4-bf16-tiny-random` is bf16 with its norms, hyper-connections and sinks kept in float32, and a bf16 forward on CPU fails inside transformers (`float != BFloat16`), so the suite loads it with `dtype=torch.float32`.

### In-place edits and read order

- `gpt2` and `gpt_bigcode` (split views of `c_attn`) and `mpt` (one `chunk()`): torch refuses in-place edits on `attention_queries`, `attention_keys`, `attention_values`; assign instead (`REFUSES_IN_PLACE_QKV`). `attention_scores` and `attention_head_outputs` accept in-place edits on every family.
- `falcon`: `mlp_output` is a copy, since the block adds the attention into the MLP's live output in place; assignment and in-place edits reach the model through an `eproperty` transform, and the copy you saved stays what you made it.
- `granite`: `attention_output` and `mlp_output` are scaled copies; assignment and in-place edits reach the model (a transform divides the edit back by `residual_multiplier`).
- `gpt_neox_japanese`: on the block whose attention has a `dense_bias` (the last), `attention_output` is the module's output plus that bias, a computed sum; assignment and in-place edits reach the model (a transform subtracts the bias back), and a read with no edit leaves the forward bit-identical.
- `xglm`: the queries, keys, values, scores, pattern and head outputs are views of the `[batch * heads, ...]` tensors the forward holds, so in-place edits reach the model; an assignment is reshaped back.
- `deepseek_v4`: `attention_keys` and `attention_values` are one tensor object, so an in-place edit of either edits both; assigning one gives it a tensor of its own.
- `falcon`: in one trace, `attention_values` before `attention_queries` or `attention_keys` (the values bind before the rotary embedding that produces the queries and keys).
- Every family: a block's interior values before that block's `attention_output`; `model.input_ids` / `attention_mask` / `input_size` before any block.

### Logits, scales and sizes

`gemma2`, `vaultgemma`, `gemma4_text` and `gemma4_unified_text` softcap their logits (`gemma3_text` only as a `Gemma3ForCausalLM` whose config sets the cap, which no released checkpoint does; the `Gemma3ForConditionalGeneration` wrapper never caps, and its lens follows) (`final_logit_softcapping`, read off the text config on a wrapper): `model.logits` is the capped output, `model.lm_head.output` the raw projection, and `project_on_vocab` applies the cap after the head so a logit lens at the last block equals `logits`. `cohere` and `cohere2` multiply the head's output by `logit_scale`, `falcon_h1` by `lm_head_multiplier`, `hyperclovax` by `logits_scaling`, `granite` divides it by `logits_scaling` (and `granitemoe`, `granitemoeshared`, `granitemoehybrid`, `granite_swa`, `granitemoe_swa` import Granite's), `mamba` and `falcon_mamba` cast the stream to the head's dtype and return float32 logits, `mamba2` and `nemotron_h` return float32 logits, and `deepseek_v4` collapses its parallel streams with `hc_head` before the norm; each family module defines `project_on_vocab(model, hidden)` with that step in place of the cap, and it is bound in the root's place (`StandardizedCapability`). `qwen3`, `qwen3_moe` and `gemma` set `head_dim` in the config to something other than `hidden_size // num_heads`; the root's plain rule reads the config's.

Each root size is a `StandardizedProperty`: the plain rule over the config, unless the family module defines a function of the same name. The families that do: `falcon` (`num_kv_heads`: `config.num_kv_heads` on the 40B layout, 1 under `multi_query`, else `num_heads`; `intermediate_size`: `ffn_hidden_size`), `deepseek_v2`, `deepseek_v3`, `kimi_k2`, `kimi_linear`, `deepseek_v32`, `glm_moe_dsa`, `glm4_moe_lite` and `youtu` (`head_dim`: `v_head_dim`; `qk_head_dim`: `qk_nope_head_dim + qk_rope_head_dim`), `mimo_v2_flash` (`head_dim`: `v_head_dim`; `qk_head_dim`: the config's `head_dim`), `gpt_bigcode` (`num_kv_heads`: 1 under `multi_query`, else `num_heads`; `intermediate_size`: `n_inner`, `4 * hidden_size` when `None`), `gpt2` and `gptj` (`intermediate_size`: `n_inner`, `4 * hidden_size` when `None`), `gpt_neo` (`intermediate_size`: `config.intermediate_size`, `4 * hidden_size` when `None`), `codegen` (`intermediate_size`: `n_inner`, `4 * hidden_size` when `None`), `opt` and `xglm` (`ffn_dim`), `gpt_neox_japanese` (`hidden_size * intermediate_multiple_size`), `mpt` (`expansion_ratio * hidden_size`), `bloom` (`4 * hidden_size`), `mamba2` (`num_heads`: `config.num_heads`, the SSD heads; `intermediate_size`: `expand * hidden_size`, the mixer's inner width), `gemma4_text` and `gemma4_unified_text` (`head_dim`, `num_kv_heads`: the config's top-level values as stored, which transformers marks per-layer and refuses as a plain `config.head_dim`), `granitemoehybrid` (`intermediate_size`: `shared_intermediate_size`, the width of the shared expert that `mlp` names), `zaya` (`intermediate_size`: `moe_intermediate_size`; the config has no dense width), `dbrx` (`intermediate_size`: `ffn_config.ffn_hidden_size`, the experts' width; every MLP is a mixture), `llama4_text` (`intermediate_size`: `intermediate_size_mlp`, the dense MLP's width; the config's `intermediate_size` is the experts'). The plain rule reads the text config (a wrapper's `text_config`, else the config itself). Every other family, and every other size on these, is the plain rule ([../usage/root-values.md](../usage/root-values.md#sizes)).

A root size equals every block's where the blocks agree. Where they differ, each block's own is on its attention and MLP, read off the module (`layers[i].self_attn.num_heads`, `.num_kv_heads`, `.head_dim`, `.qk_head_dim`; `layers[i].mlp.intermediate_size`, one routed expert's on a mixture): Gemma-4's full blocks (`head_dim`, and `num_kv_heads` on 26B-A4B/31B), MiMo-V2-Flash's sliding blocks (twice the key/value heads), Gemma-4 E2B's KV-sharing blocks (a double-width MLP under `use_double_wide_mlp`), and Laguna's blocks under `num_attention_heads_per_layer` (their own query-head counts). The base `Attention` and `Mlp` read every family's modules; `jetmoe`'s and `granitemoehybrid`'s `Mlp` override `intermediate_size` (the module's `hidden_size`).

## Reproducing the sweep

The table's `support()` column comes from one script that loads every pinned checkpoint above (olmo3 excepted) with `dispatch=True, attn_implementation="eager"` (plus `dtype=torch.float32` for DBRX) and prints `model.support()`. The one-family version:

```python
import torch
from nnterp import StandardizedTransformer

model = StandardizedTransformer("yujiepan/dbrx-tiny256-random", dispatch=True, attn_implementation="eager", dtype=torch.float32)
print({name: reason for name, reason in model.support().items() if reason})   # {}
```

`HF_HUB_OFFLINE=1 pytest tests/families` runs the suite behind every row: each family's test file pins its checkpoint, native paths and quirks as class attributes (`NATIVE`, `EXPECTED_UNAVAILABLE`, `REFUSES_IN_PLACE_QKV`, `ATTENTION_SINK`, `KV_HEADS_EXPANDED`, `MLP_WIDTH_KEY`, `LOAD_KWARGS`, `QUERY_GATED`, `ATTENTION_NORM`, `MLP_NORM`, `MLP_NORM_BEFORE_ATTENTION`, `MOE_UNAVAILABLE`, `ROUTER_EXTRA_CLASSES`), and `tests/families/suite.py` is the executable form of every claim above.

## Gotchas

- `support()` on a hybrid returns per-block dicts for every `self_attn.*` and `linear_attn.*` key; `support(layer=i)` is the flat view for one block.
- The interior values report unavailable under the checkpoint's default `sdpa` on every interface family; `StandardizedTransformer` does not force eager. BLOOM, MPT, CodeGen, XGLM and GPT-NeoX-Japanese load eager and their pattern has no such predicate.
- Falcon's interior values name their operations by `config.alibi` (`by_alibi`), so an alibi checkpoint reports nothing unavailable under eager; the read order inside one trace differs by branch (see the row). The suite runs the 7B checkpoint on both branches (`TestFalconAlibi` on a copy with `alibi: true` in its config).
- `num_kv_heads` is the config's number; `attention_keys.shape[1]` is `num_heads` on the latent-attention families, JetMoE and Falcon's 40B layout, where the keys are expanded before the interface, and twice `num_kv_heads` on MiMo-V2-Flash's sliding-window blocks.
- A family's `input_layernorm` / `post_attention_layernorm` aliases are names, not meanings: on a sandwich block the post-attention norm follows the attention, on a parallel block one norm feeds both sublayers, on OLMo-2/3 and Falcon-40B there is no `input_layernorm`. Use `self_attn.input` and `mlp.input` for what enters a sublayer.
- `llama4_text`: every tiny `llama4` checkpoint on the Hub gives `attn_temperature_tuning` as an int, which transformers 5.17 rejects, so the pinned one loads only with the rewrite `tests/families/test_llama4_text.py` performs; the one `Llama4ForCausalLM` tiny checkpoint (`trl-internal-testing/tiny-Llama4ForCausalLM`) loads but returns NaN logits.
- `gemma4_text`'s `hf-tiny-v2/tiny-random-Gemma4ForCausalLM` has a 99-row per-layer embedding table, so every real prompt overflows it in plain transformers; the test tiles it to the full vocabulary in a copy. It is also the only tiny checkpoint that carries per-layer embeddings, experts and KV sharing at once.
- `gemma4_text`: `skip_layers` over a block whose keys and values later blocks borrow fails inside transformers with a `KeyError` naming the layer kind; see [Borrowed keys and values](#borrowed-keys-and-values).
- `ministral`'s tiny checkpoint ships only `tekken.json`, which transformers loads through `mistral_common`; `tests/families/test_ministral.py` re-initialises its config with the tiny Mistral checkpoint's `tokenizer.json` and vocabulary. No public checkpoint on the Hub has `model_type` `ministral` (Ministral-8B is `mistral`).
- `zaya`'s tiny checkpoint has `qk_norm.temp` at zero, which zeroes every key, so its pattern is uniform and its queries inert; the test sets it to one in a copy. `yujiepan/zaya1-tiny-random` does not parse on transformers 5.17 (`rope_scaling: false`).
- `zamba` and `zamba2` are not shipped. Both hybrid blocks add a shared transformer's output, projected by `linear`, to the Mamba mixer's input rather than to the residual stream, so the standard contributions have no meaning there; on Zamba the shared transformer is also one module under every hybrid block, one envoy, so `layers[i].shared_transf` reads the first block's call on every block.
- `kimi_k2` is looked up from the text config's `model_type`, which the released Kimi K2.5/K2.6/K2.7-Code configs set to `kimi_k2` (transformers keeps it on the `DeepseekV3Config` it builds). The text-only Kimi K2 checkpoints carry `kimi_k2` at the top, which `AutoConfig` refuses without `trust_remote_code`, and the remote code builds Moonshot's own classes, which no family keys; `StandardizedTransformer(DeepseekV3ForCausalLM.from_pretrained(repo), tokenizer=...)` loads them on the native classes. Kimi-VL (`kimi_vl`) and Kimi K3 (`kimi_k3`, whose text model extends Kimi-Linear) load only through remote code and are not shipped.
- `kimi_linear`'s tiny checkpoint leaves its last block out of `linear_attn_config`, which transformers 5.17 refuses; `tests/families/test_kimi_linear.py` types it `full_attention` in a copy, as the released checkpoints type their last block.
- `olmo3`'s tiny checkpoint predates the per-layer-type rope config and loads only with the rewrite `tests/families/test_olmo3.py` performs; examples in these docs use the other families.
