03 · what to know before you trace

The block, in order

h   = x + self_attn(input_layernorm(x))          # multi-head latent attention
out = h + mlp(post_attention_layernorm(h))       # a dense MLP on block 0, a mixture of experts after

DeepSeek-V3's pre-norm block, Llama's names. first_k_dense_replace is 1: block 0's mlp is a dense MLP and the other 60 blocks' a mixture. The block adds each sublayer's output to the stream and returns a tensor, so the identity is the plain sum:

with model.trace(prompt):
    x = model.layers[1].input.save()
    attn = model.layers[1].self_attn.attention_output.save()
    mlp = model.layers[1].mlp.mlp_output.save()
    out = model.layers[1].layer_output.save()

torch.testing.assert_close(x + attn + mlp, out)

Loading a text-only K2 checkpoint

Kimi-K2-Instruct, -Instruct-0905, -Base and -Thinking say kimi_k2 at the top of their config. AutoConfig maps that type only through the checkpoints' remote code, which builds its own copy of DeepSeek-V3's classes, and no nnterp family covers those classes. transformers' DeepseekV3ForCausalLM reads the same config. Load it and hand the module over, with the checkpoint's tokenizer (which also needs the remote code):

from transformers import AutoTokenizer, DeepseekV3ForCausalLM

repo = "moonshotai/Kimi-K2-Instruct"
module = DeepseekV3ForCausalLM.from_pretrained(repo, attn_implementation="eager")
tokenizer = AutoTokenizer.from_pretrained(repo, trust_remote_code=True)
model = StandardizedTransformer(module, tokenizer=tokenizer)

The loaded config keeps model_type kimi_k2, and nnterp finds the family from it: DeepSeek-V3's (nnterp/families/deepseek_v3.py) under that name. The weights are stored quantized, as each config's quantization_config says: FP8 blocks on K2-Base, -Instruct and -Instruct-0905, 4-bit integer groups (compressed-tensors) on K2-Thinking and the K2.5 line. K2.5, K2.6 and K2.7-Code wrap the same text model in Kimi_K25ForConditionalGeneration, under model.language_model. Their text_config says kimi_k2, but transformers' Kimi_K25Config loads it as deepseek_v3, so nnterp finds the family from the wrapper's own type instead: kimi_k25, which is this family under the wrapper's name (model.family reads kimi_k25). The standard names are the same.

Latent attention: queries and keys are wider than values

Queries and keys are qk_head_dim wide (qk_nope_head_dim + qk_rope_head_dim, 128 + 64), values head_dim (v_head_dim, 128). model.qk_head_dim and model.head_dim give the two widths. Rotary turns only the last qk_rope_head_dim dimensions of each query and key, and that part of the key comes from one projection per token, shared by every head. Keys and values are expanded from one latent per token (kv_lora_rank 512) for every head, so attention_keys has num_heads (64) heads, as many as the queries. The attention interior needs attn_implementation="eager".

As on DeepSeek-V3, the rotary part is served in rotate-half order (rope_interleave is true): the projection's even rotary dimensions, then its odd ones. The scores are scaled by qk_head_dim ** -0.5 times YaRN's factor, which depends on the context extension: self_attn.scaling is 0.1309 on K2-Base and K2-Instruct (rope_scaling factor 32) and 0.1447 on the others (factor 64).

The mixture of experts

384 routed experts, 8 per token, and one shared expert every token runs through. router_logits are the logits before the sigmoid. The router picks 8 experts by the sigmoid plus a selection bias, with one expert group (n_group 1), so every expert is a candidate. expert_weights are the chosen sigmoids without the bias, renormalized and multiplied by routed_scaling_factor (2.827), so they sum to 2.827 at every token. The mixture's output is routed_output + shared_expert_output:

moe = model.layers[1].mlp
with model.trace(prompt):
    weights = moe.expert_weights.save()                     # [batch, seq, top_k]: 8 on K2
    routed = moe.routed_output.save()
    shared = moe.shared_expert_output.save()
    out = moe.mlp_output.save()

torch.testing.assert_close(routed + shared, out)

Block 0's MLP is dense: support() reports every mixture value missing there.

The readout and the embeddings

logits is lm_head.output: no softcap and no scale. lm_head has its own weight. The embedding is not scaled, so token_embeddings equals layers[0].input.

quirks

Latent attention

Keys and values are projected up from a small latent shared by the heads; queries and keys are qk_head_dim wide, values head_dim wide.

Interleaved rotary

Rotary rotates adjacent pairs of dimensions (2i, 2i + 1), not i with i + rot/2 as rotate_half does, so a query or key head's dimensions pair up differently from a rotate_half family's. Where the attention rotates the even and odd slices (apply_rotary_pos_emb_interleave), the rotated queries and keys come out in rotate_half order, evens first.

Mixture of experts

On every block or some, the MLP is a mixture of experts: layers[i].mlp serves router_logits, expert_weights, expert_indices and expert_outputs, though some families leave one or more of them unavailable.

Dense first blocks

The first blocks have a dense MLP and the rest a mixture of experts, so the mixture's values exist only from the first mixture block on.

Kimi K2 (model_type kimi_k2): DeepSeek-V3's architecture under Moonshot's own model type.

Kimi K2 and its successors' language models (K2.5, K2.6, K2.7-Code) are DeepSeek-V3's DeepseekV3ForCausalLM with Moonshot's tokenizer; their configs say kimi_k2. transformers builds them with its native DeepSeek-V3 classes: the multimodal kimi_k25 checkpoints through Kimi_K25Config, whose text_config is a DeepseekV3Config with model_type deepseek_v3 (the wrapper resolves by its own type, to kimi_k25.py, which re-exports this module), and the text-only K2 checkpoints from a DeepseekV3ForCausalLM loaded directly, since AutoConfig maps no kimi_k2. The tree, the envoys and the sizes are DeepSeek-V3's (deepseek_v3.py); this module names them under kimi_k2, because the family registry is the module's file name.
