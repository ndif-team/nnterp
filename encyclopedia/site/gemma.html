One row per image (per crop on LLaVA-OneVision, per tile on Idefics 3 and SmolVLM); patches in raster order.
positions
Learned absolute position embeddings are added to the patch embeddings; no class token and no norm before block 0.

No causal mask: a patch attends to every patch of its row.

The Notes

03 · what to know before you trace

The block, in order

h   = x + self_attn(input_layernorm(x))
out = h + mlp(post_attention_layernorm(h))

Two RMSNorms per block, each before its sublayer, none after: Llama's layout and Llama's names. post_attention_layernorm is the MLP's input norm. The Gemma 2, 3 and 4 blocks add a norm after each sublayer and give this name to the norm after the attention, so a hook ported by name from those families lands on a different tensor here.

The contributions are the modules' outputs

attention_output is self_attn.output[0] and mlp_output is mlp.output, added to the stream with nothing in between. On the pinned checkpoint, in float32:

with model.trace(prompt):
    x = model.layers[1].input.save()
    attn = model.layers[1].self_attn.attention_output.save()
    mlp = model.layers[1].mlp.mlp_output.save()
    out = model.layers[1].layer_output.save()

torch.testing.assert_close(x + attn + mlp, out)

Scaling a module's output scales its contribution: mlp.output[:] *= 0.5 and mlp.mlp_output[:] *= 0.5 are the same edit.

Embeddings are scaled before block 0

embed_tokens multiplies its lookup by √hidden_size, cast to the weight's dtype first: 45.25 on 2B and 55.5 on 7B in bfloat16, where the exact roots are 45.25 and 55.43. token_embeddings is the scaled tensor and equals layers[0].input on text. The stored embedding weight is also the unembedding (tie_word_embeddings), so a row of embed_tokens.weight is a token's unembedding direction unscaled, and an edit to it changes the readout too.

The norm gain is 1 + weight

GemmaRMSNorm normalizes in float32 and multiplies by 1 + weight, then casts back. Folding a norm into the next projection, or reading its gain, uses 1 + model.norm._module.weight; the stored weight is initialized at zero.

Attention: multi-query on 2B, 256-wide heads

2B has 8 query heads over a single key/value head; 7B has 16 of each. attention_keys and attention_values are read before repeat_kv, so on 2B they are [batch, 1, seq, 256] and an edit to them reaches every query head. head_dim is 256 on both sizes, so 7B's 16 heads are 4096 wide against a hidden_size of 3072, and the query scale is head_dim ** -0.5. There is no score softcap, window or sink: the default sdpa load and attn_implementation="eager" run the same attention, and eager serves the interior values.

Every checkpoint runs the tanh GELU

The MLP is down_proj(act(gate_proj(x)) * up_proj(x)) with the config's hidden_act. The gemma-2b and gemma-7b configs (with their -it versions and codegemma-2b) say gelu, a legacy value meant as the tanh approximation of GELU. GemmaConfig rewrites it to gelu_pytorch_tanh when it loads, with a warning, so model.config.hidden_act reads gelu_pytorch_tanh and the MLP runs the tanh approximation, not the exact erf GELU. The other configs set no hidden_act and take GemmaConfig's default, the same gelu_pytorch_tanh: Gemma 1.1 and codegemma-7b write it under hidden_activation, a key GemmaConfig does not read, and PaliGemma's text config names no activation.

The readout

model.logits is model.lm_head.output: no cap and no scale, so project_on_vocab is lm_head(norm(hidden)) with the 1 + weight gain inside norm, and a logit lens at the last block equals logits.

What this family module covers

Every checkpoint whose config says model_type gemma: Gemma 2B and 7B with their instruction-tuned -it and 1.1 releases, CodeGemma 2B and 7B, and the text model inside PaliGemma 1. PaliGemma 2 wraps a Gemma 2 text model (its text_config.model_type is gemma2), so it is not this family's.

Vision notes

· SigLIP · PaliGemma

The SigLIP vision encoder

The patch axis is the patch grid

No class token: vision.patch_embeddings, every block's layer_output and vision.tower_output have the same length, (image_size // patch_size) ** 2 patches per image or tile, in raster order. Row r, column c of the grid is index r * (image_size // patch_size) + c on every value of the vision encoder.

The final norm is vision.norm

post_layernorm norms every patch after the last block, so vision.tower_output == vision.norm(vision.layers[-1].layer_output). Each wrapper's notes say whether its projector reads tower_output or a block's layer_output before the norm.

PaliGemma

The projector is one linear over tower_output

model.multi_modal_projector (the projector) is a single linear with a bias, 1152 → 2048 on every PaliGemma size. It reads the vision encoder's last_hidden_state, the patches after post_layernorm, so model.projector.input == model.vision.tower_output, and a write to the last block or to tower_output reaches the text model. vision.image_features is model.projector.output flattened over the images. On the pinned tiny checkpoint:

with model.trace(prompt, images=[image]):
    mask = model.vision.image_token_mask.save()
    out = model.vision.tower_output.save()
    fed = model.projector.input.save()
    projected = model.projector.output.save()
    features = model.vision.image_features.save()
    first = model.layers[0].input.save()

torch.equal(fed, out)                             # True: the projector reads tower_output
torch.equal(projected.flatten(0, 1), features)    # True
torch.equal(first[mask], features)                # True: the scatter

One image token per patch

The projector maps each patch to one token, so an image is (image_size // patch_size) ** 2 image tokens: 256 on the 224 checkpoints (16 × 16 patches of 14 pixels), 1024 on the 448 checkpoints and 4096 on paligemma-3b-pt-896 (the config's num_image_tokens). The processor resizes every image to the checkpoint's image_size, so every image of a checkpoint gives the same count.

The image comes first, unscaled

The processor puts the image tokens before the beginning-of-sequence token, then the prompt and a newline: on the pinned tiny checkpoint positions 0 to 15 are the image, 16 is <bos>. The wrapper scatters model.projector.output into the output of embed_tokens as it is, so the text rows of layers[0].input carry the √hidden_size scale and the image rows carry none: layers[0].input[~mask] == token_embeddings[~mask]. The wrapper numbers positions from 1 (position_ids is arange(seq) + 1), so a text token sits one rotary step later than on a GemmaForCausalLM.

The prefix attends in both directions

The processor marks the image and the prompt as the prefix (token_type_ids 0) and any suffix passed to it as 1. The wrapper's mask lets every prefix position attend to every other prefix position, later ones included; only suffix tokens are causal. A trace with an image and a prompt is therefore bidirectional over the whole sequence: on the pinned tiny checkpoint block 0's attention_probabilities carry weight above the diagonal. A text-only trace with the tokenizer's encoding passes no token_type_ids and is causal.

A text-only trace takes the tokenizer's encoding

PaliGemma's processor refuses a prompt without an image. A text-only trace of the wrapper takes the tokenizer's encoding instead; the mask is then all false and vision.image_features is never reached.

with model.trace(dict(model.tokenizer(text, return_tensors="pt"))):
    logits = model.logits.save()
