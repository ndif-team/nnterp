The Notes

03 · what to know before you run

The block, in order

h   = x + self_attn(input_layernorm(x))      # multi-head latent attention
out = h + mlp(post_attention_layernorm(h))   # dense on block 0, a mixture after

Llama's pre-norm block and Llama's names. first_k_dense_replace is 1 on every released checkpoint: block 0's mlp is a dense MLP, every later block's a mixture. The block adds each sublayer's output to the stream and returns a tensor, so the identity is the plain sum, on the dense block as on a mixture block:

with model.trace(prompt):
    x = model.layers[1].input.save()
    attn = model.layers[1].self_attn.attention_output.save()
    mlp = model.layers[1].mlp.mlp_output.save()
    out = model.layers[1].layer_output.save()

torch.testing.assert_close(x + attn + mlp, out)

Latent attention: queries and keys are wider than values

attention_queries and attention_keys are [batch, num_heads, seq, qk_head_dim], with qk_head_dim = qk_nope_head_dim + qk_rope_head_dim (128 + 64 = 192); attention_values and attention_head_outputs are head_dim wide, which nnterp reads from v_head_dim (128). transformers sets the config's head_dim to qk_rope_head_dim (64), the rotary part's width, which no served value has. The attention interior needs attn_implementation="eager".

attn = model.layers[1].self_attn
with model.trace(prompt):
    q = attn.attention_queries.save()          # [1, 16, seq, 192] on V2-Lite
    v = attn.attention_values.save()           # [1, 16, seq, 128]

Keys and values are expanded from one compressed latent per token (kv_lora_rank, 512) by kv_b_proj, so attention_keys has num_heads heads, as many as the queries. The last qk_rope_head_dim dimensions of a key come from one projection per token, shared by every head: attention_keys[:, h, :, -64:] is the same tensor for every h, and an edit there has to be made on every head to act like an edit to the shared part.

Query compression differs between the sizes

DeepSeek-V2, V2.5 and Coder-V2 (236B) compress the queries too (q_lora_rank 1536): q_a_proj, q_a_layernorm and q_b_proj, with no q_proj module. V2-Lite and Coder-V2-Lite (16B) have q_lora_rank null: one q_proj, and no q_a_proj, q_a_layernorm or q_b_proj. attention_queries is read at the attention interface on both, the same width.

Rotary turns adjacent pairs in place

The rotary part is rotated as complex numbers over adjacent pairs of dimensions (2i, 2i + 1), in place, so the last 64 dimensions of attention_queries and attention_keys keep the order of the projection's output.

The query scale carries YaRN's factor

Every released checkpoint extends the context with YaRN (rope_scaling factor 40), and the attention multiplies the scores by qk_head_dim ** -0.5 times a factor set by mscale_all_dim. Where mscale_all_dim is 0.707 (V2, V2-Chat and the Lite models) the factor is 1.59 and self_attn.scaling is 0.1147. Where it is 1.0 (V2-Chat-0628, V2.5, V2.5-1210 and the 236B Coder-V2 models) the factor is 1.87 and self_attn.scaling is 0.1352. Recompute attention_scores from the queries and keys with self_attn.scaling, not with qk_head_dim ** -0.5.

The mixture: a softmax router whose weights are not renormalized

Every block after the first routes each token to num_experts_per_tok (6) of n_routed_experts experts (64 on Lite, 160 on the 236B models) and runs it through n_shared_experts (2) shared experts, one MLP 2 × moe_intermediate_size wide. router_logits are the logits before the softmax. expert_weights are the chosen experts' softmax probabilities times routed_scaling_factor, never renormalized over the chosen six. On the Lite models the factor is 1.0, so a token's weights sum to less than one. On the 236B models it is 16.0. The 236B models route group_limited_greedy (topk_method): the experts sit in n_group 8 groups, each group scored by its best expert, and a token chooses its six among the experts of its best topk_group 3 groups. The Lite models route greedy, over every expert.

moe = model.layers[1].mlp
with model.trace(prompt):
    logits = moe.router_logits.save()
    w = moe.expert_weights.save()
    idx = moe.expert_indices.save()
    routed = moe.routed_output.save()
    shared = moe.shared_expert_output.save()
    out = moe.mlp_output.save()

scale = model.config.routed_scaling_factor
torch.testing.assert_close(w, logits.softmax(-1).gather(-1, idx) * scale)   # greedy and group-limited
torch.testing.assert_close(routed + shared, out)

The shared experts run after the routed experts. Ablating an expert is zeroing the weight of every slot that chose it. The shared experts are untouched:

with model.trace(prompt):
    moe.expert_weights = moe.expert_weights.masked_fill(moe.expert_indices == 3, 0)
    ablated = model.logits.save()

Block 0's MLP is dense: support() reports every mixture value missing there.

quirks

Latent attention

Keys and values are projected up from a small latent shared by the heads; queries and keys are qk_head_dim wide, values head_dim wide.

Interleaved rotary

Rotary rotates adjacent pairs of dimensions (2i, 2i + 1), not i with i + rot/2 as rotate_half does, so a query or key head's dimensions pair up differently from a rotate_half family's. Where the attention rotates the even and odd slices (apply_rotary_pos_emb_interleave), the rotated queries and keys come out in rotate_half order, evens first.

Mixture of experts

On every block or some, the MLP is a mixture of experts: layers[i].mlp serves router_logits, expert_weights, expert_indices and expert_outputs, though some families leave one or more of them unavailable.

Dense first blocks

The first blocks have a dense MLP and the rest a mixture of experts, so the mixture's values exist only from the first mixture block on.
